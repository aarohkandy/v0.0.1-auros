Code signing policy

AurOS Setup is the one file you download and open. A signature from SignPath Foundation would say that this file came out of the build described below and that nobody changed it afterwards. It would not say that the program is safe, and it would not mean the Foundation vouches for what AurOS does. This page says who may sign it, how that is done, and what a signature does not promise.

Where this stands today

AurOS Setup has no signature yet. That is why Windows asks a few extra questions before it opens (the simple page shows them). We plan to apply to SignPath Foundation, which gives free signing certificates to open-source projects. When it is granted, every release of AurOS Setup will be signed as described below, and this page will say so.

Not in use yet. If the application is accepted, this page will say: free code signing provided by SignPath.io, certificate by SignPath Foundation. SignPath is not connected to AurOS today.

A signature is not a promise that a program is good. It says who published it and that it is unchanged since they did. Windows may still ask a new file a question or two until enough people have opened it.

What is signed, and by whom

  • Only AurOS Setup (AurOS-Setup.exe), the Windows program on the download button. Nothing else we publish is signed this way.

  • Only a file built from the source code in the open, on GitHub’s own build computers, from the public project page. Never a file built on someone’s own computer, and never a file from another project.

  • The signature is made by SignPath, which keeps the key in secure hardware. Nobody on the AurOS team ever holds the key.

Who decides

Three jobs, each with a name. Today one person holds all three; when the team grows, more people will be listed here.

  • Author (may change the code without a second look): @aarohkandy.

  • Reviewer (looks at every change that comes from anyone else before it is accepted): @aarohkandy.

  • Approver (says yes, by hand, to each release before it is signed): @aarohkandy.

Everyone in these jobs signs in to GitHub and to SignPath with a second step (two-factor sign-in), so a stolen password alone is not enough.

How a release gets its signature

  1. A new version is built from the public source on GitHub, and tested: the installer and the system it installs are started in virtual computers.

  2. The build sends the finished AurOS Setup to SignPath. SignPath checks that it really came from this project’s build on GitHub, not from someone holding a password.

  3. The approver looks at the release and approves it, or doesn’t. Nothing is signed until a person says yes.

  4. The signed file comes back. The build checks the signature, and checks that the file inside is exactly the one it sent, byte for byte apart from the signature itself. If either check fails, nothing is published.

  5. The signed file is started on a real Windows computer, and a whole install is run with it, before it becomes the download on the front page.

Privacy

AurOS Setup does not send any information about you or your computer to us. The only thing it asks the internet for is AurOS itself: when you press Install it downloads the pieces of AurOS from GitHub, which is the one thing you asked it to do. GitHub sees your internet address, as it does for any download. Nothing is sent to the AurOS project. More on the privacy page.

The website uses no cookies and no tracking, and loads nothing from any other server.

Back to the top

If something looks wrong

If a file says it is AurOS Setup but you think it is not ours, or a signature looks wrong, don’t open it. Tell us on the AurOS project page, or read how to report a security problem privately on the security page. Don’t include passwords or anything else private.

AurOS will never phone you. Nobody from AurOS will ever ask to connect to your computer, or ask for a card number, a password or gift cards.
