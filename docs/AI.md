# Wishes: AurOS's AI layer (contract v0)

> Owner, 2026-10-23: "there needs to be at least a bit of AI ... if I want an
> OS where every time I accidentally write the word potato it fills my screen
> with potatoes, or every time my gyro points north it makes the screen
> brighter, that needs AI ... some integration with Claude."

She says (or types) what she wants her computer to do. A few seconds later
AurOS tells her, in one plain sentence, what it will do, and she presses
**Yes**. From then on her computer does it. Every wish can be seen, switched
off and removed in one place. This file is the contract between the three
streams that build it: **W1** (the engine on the computer), **W2** (what she
sees and says), **CL** (the cloud service). Change it only by a commit that
all three read.

## 1. The safety model (non-negotiable)

1. **Claude never runs code on her computer.** The cloud turns her words into
   a *wish*: a small JSON document in the fixed vocabulary below. The engine
   on her computer validates it against its own copy of the schema and runs
   only what it knows. Unknown fields or types: the wish is refused.
2. **She confirms every wish** from its plain-words `summary`, generated by
   the cloud but re-rendered locally from the validated fields (the device
   writes its own sentence; it never shows unvalidated model text as the
   description of what will happen).
3. **Nothing a wish does can hurt her**: no files deleted or moved, no
   messages or e-mails sent, no purchases, no passwords, no network or
   security settings, no turning off updates/firewall/scam guards, no
   keystrokes leaving the computer. Hard caps in the engine (§3.3) bound
   every action. Any overlay vanishes at the first key or click.
4. **Privacy**: the only thing sent is the text of her wish (or question),
   her language, and a capability list (which sensors and looks exist, which
   programs are installed). Never keystrokes, file names, contacts, location.
   First use shows one plain consent screen; "No" leaves Wishes off.
5. **Typed-word triggers stay local**: the compositor matches what she types
   against the few registered trigger words and emits only "word X typed".
   Nothing she types is stored or sent.
6. **Offline / service off**: Wishes says so in one line and the rest of the
   computer is unaffected.

## 2. The wish document (v1)

```json
{
  "v": 1,
  "title": "Potatoes!",
  "summary": "Every time you type the word potato, your screen fills with potatoes for 3 seconds.",
  "when": { "type": "typed_word", "word": "potato" },
  "do": [ { "type": "fill_screen", "emoji": "🥔", "seconds": 3 } ],
  "enabled": true
}
```

`title` ≤ 40 chars, `summary` ≤ 160 chars, `do` 1–4 actions.

### 2.1 `when` (exactly one)

| type | fields | notes |
|---|---|---|
| `now` | – | a one-off change (e.g. "make the text bigger") |
| `typed_word` | `word` (2–32 letters) | local match, case-insensitive, whole word |
| `time` | `at` "HH:MM", `days` ["mon",...] or omitted = every day | |
| `every` | `minutes` 5–1440 | |
| `startup` | – | after she logs in |
| `app_opened` | `app` (desktop id from caps) | |
| `battery_below` | `percent` 5–50 | |
| `plugged_in` / `unplugged` | – | charger |
| `usb_inserted` | – | |
| `idle` | `minutes` 1–240 | no input for that long |
| `sensor` | `sensor` ∈ `compass`,`tilt`,`light`; `compass`: `heading` ∈ north/east/south/west, `tolerance_deg` 5–45; `tilt`: `orientation` ∈ normal/left/right/upside_down; `light`: `below_lux` / `above_lux` | only offered when caps list the sensor |

### 2.2 `do` (1–4, run in order)

| type | fields | engine caps (§3.3) |
|---|---|---|
| `fill_screen` | `emoji` (one emoji) or `text` (≤ 24 chars), `seconds` 1–10 | ≤ 10 s, ≤ 12/hour, dismiss on any input |
| `show_message` | `text` ≤ 140, `seconds` 3–60 | calm card, dismiss on input |
| `remind` | `text` ≤ 140 | a reminder card that stays until she presses OK |
| `speak` | `text` ≤ 200 | on-device voice |
| `play_sound` | `sound` ∈ chime, bell, birds, applause, gentle | volume ≤ her current level |
| `brightness` | `set_percent` 10–100 or `change_percent` −50..+50 | never below 10 % |
| `volume` | `set_percent` 0–80 or `change_percent` −50..+50 | never above 80 % from a wish |
| `open_app` | `app` (desktop id from caps) | |
| `open_website` | `url` https only, no IP literals, no credentials in URL | shown in the confirmation; S2's scam guard applies |
| `install_program` | `flathub_id` | always asks her again in the store; S2's remote-access warning applies |
| `set_look` | `look` ∈ taskbar, dock, rail, tiles | |
| `set_text_size` | `size` ∈ normal, bigger, biggest | |
| `set_wallpaper` | `color` (#RRGGBB) or `theme` (installed theme name) | |
| `night_light` | `on` bool | |

## 3. The engine on her computer (W1: `src/aurwish/`)

1. `aurwish` runs as her user (never root), reads/writes
   `~/.local/share/auros/wishes.json` (0600), validates every wish with the
   v1 schema compiled in (no network schema fetch), and runs triggers/actions.
2. Event sources: compositor events (typed words, app opened, idle), upower
   (battery, AC), udev (USB), iio-sensor-proxy (compass, tilt, light),
   timers. Actions via the shell's existing control paths (brightness,
   volume, look, text size, theme) and an overlay surface drawn by the shell.
3. **Caps** (in code, tested): the table limits above; a global limit of
   60 actions/hour across all wishes; a wish that hits a cap is paused and
   she is told once, plainly; a crash or bad file never blocks login
   (wishes are skipped, the shell starts).
4. "My wishes" (Settings): each wish's sentence, an on/off switch, Remove;
   "Turn off all wishes". Removing the last wish leaves nothing running.

### 3.7 The socket between the shell and the engine (W1 owns it; W2 follows it)

Numbered 3.7 because §7 below adds a §3.5 and §3.6. Adopted from W2's
proposal (`docs/handoff/streams/W2.md`) with the additions §7 needs.

- `$XDG_RUNTIME_DIR/aurwish.sock`, AF_UNIX `SOCK_STREAM`, made by the engine,
  mode 0600; the engine refuses any peer whose `SO_PEERCRED` uid is not its
  own. One JSON object per line, UTF-8, at most **4096 bytes a line from the
  shell** and **65536 from the engine** (a `list` of 50 wishes is long). A
  line that is too long or not a JSON object closes that connection. At most 4
  connections. Events go only to connections that have said `hello`.
- **The shell never talks to the cloud and never validates a wish.** The engine
  is the only cloud client and the only author of every sentence she reads
  (`sentence`, `title`, `text` of a `notice`/`cannot`). The shell shows them
  as given. In a `sentence`, `*` toggles bold (free text can never contain
  `*`, §7.3).
- Requests carry an integer `id`; the reply echoes it. Unknown `op` →
  `{"id":N,"kind":"error","error":"refused"}`.

Shell → engine:

| line | reply |
|---|---|
| `{"op":"hello","id":1}` | `{"id":1,"kind":"hello","v":1,"consent":bool,"all_off":bool,"sensors":{"compass":bool,"tilt":bool,"light":bool}}` then a `triggers` event |
| `{"op":"consent","id":2,"version":1,"yes":true}` | `done` (no → Wishes stay off, nothing is ever sent) |
| `{"op":"wish","id":3,"text":"…","lang":"en","voice":false}` | `wish` · `cannot` · `error` (the engine calls the cloud). `error`/`consent` until she has agreed; `error`/`busy` while another is in flight; `error`/`refused` for text under 3 or over 300 characters or the same text within 30 s |
| `{"op":"ask","id":4,"text":"…","lang":"en","look":"rail"}` | `help` · `error` (`look` is optional) |
| `{"op":"check","id":5,"wish":{v1 doc},"said":"…","voice":false}` | `wish` · `cannot` — a wish built on the device (the gallery), never sent anywhere |
| `{"op":"cancel","id":3}` | none; the cloud request for id 3 is stopped |
| `{"op":"confirm","id":6,"pending":"p7"}` | `{"id":6,"kind":"done","wid":"w3"}` (a `now` wish runs at once and has no `wid`) |
| `{"op":"discard","id":7,"pending":"p7"}` | `done` |
| `{"op":"list","id":8}` | `{"id":8,"kind":"list","all_off":false,"undo":bool,"wishes":[{"wid","title","sentence","status","last_ran"}]}` |
| `{"op":"enable","id":9,"wid":"w3","on":false}` | `done` — this is also **Stop this wish** |
| `{"op":"remove","id":10,"wid":"w3"}` | `done` |
| `{"op":"test","id":11,"wid":"w3"}` | `done` — runs it once now; limits still apply |
| `{"op":"all_off","id":12}` / `{"op":"all_on","id":13}` | `done` |
| `{"op":"undo","id":14}` | `done` — Undo my last wish (10 minutes) |
| `{"op":"restore","id":15}` | `done` — Put everything back how it was |
| `{"op":"keep","id":16,"wid":"w3","yes":true}` | `done` — answer to a `keep_it` card |
| `{"op":"snooze","id":17,"wid":"w3"}` | `done` — Remind me in 10 minutes |
| `{"op":"today","id":18}` | `{"id":18,"kind":"today","items":[{"wid","title","times"}]}` |
| `{"op":"forget","id":19}` | `done` — Forget everything (wishes.json, token, install id) |

Shell → engine, no reply (the compositor's half; §1.5, §7.6):

| line | when |
|---|---|
| `{"op":"typed","word":"potato"}` | the compositor matched a word from the latest `triggers` list (never any other word) |
| `{"op":"app","app":"firefox"}` | a window whose app id is in the latest `triggers` list was opened |
| `{"op":"input"}` | she pressed a key or moved/clicked, at most once a second (idle and "3 s with no typing") |
| `{"op":"hold","reasons":["call"]}` | the full current set of §7.6 reasons: `password` `call` `camera` `microphone` `share` `fullscreen` `lock`; `[]` clears |
| `{"op":"did","n":42,"ok":true,"prev":{v1 action}}` | the shell carried out `shell` event 42; `prev` is the action that would put it back (for Undo) |

Engine → shell replies (`kind`): `wish` `{"id","kind":"wish","pending":"p7","sentence","title","outward"?:{"name","host"?}}`;
`cannot` `{"id","kind":"cannot","missing":"<reason>","text","alt"?:{"pending","sentence","title","outward"?}}`
where `<reason>` is `unclear question compass tilt light install files messages money private security app theme site duplicate limit other`,
`text` is the device's sentence for it, and `alt` (when present) is the nearest wish the engine
can do, already checked and waiting for her Yes ("I can't do that, but I can …");
`help` `{"id","kind":"help","page":"<help page id>"|null,"pending"?,"sentence"?,"title"?}`
(`page` is a plain name of a file in `/usr/share/auros/help/` that exists; `pending` etc. when the answer comes with an offer);
`error` `{"id","kind":"error","error":"offline|busy|resting|limit|refused|consent|broken","text","retry_after"?}`
(`retry_after` in seconds, at most 3600; `limit` and `resting` carry the service's);
`done` `{"id","kind":"done"}`.

Engine → shell events (no `id`; `n` numbers them; `wid`/`title` say whose wish it is
so every card can show "Your wish "X" — [Stop this wish]"; `tell` is true for a
wish's first 3 runs):

```
{"ev":"triggers","words":["potato"],"apps":["firefox"]}   on hello and on every change; ≤10 words
{"ev":"changed"}                                          My wishes should re-list
{"ev":"fill","n":1,"wid":"w3","title":"…","emoji":"🥔","seconds":3,"tell":true}   or "text":"HELLO"
{"ev":"message","n":2,"wid","title","text","tell"}         stays until she closes it
{"ev":"remind","n":3,"wid","title","text","for":"9:00 am"?,"private":false}
{"ev":"shell","n":4,"wid","title","do":{v1 action}}        set_look set_text_size set_wallpaper
                                                          night_light pointer_size open_app open_website
                                                          do_not_disturb; answered with "did"
{"ev":"notice","text":"…"}                                 one plain sentence the engine wrote
{"ev":"keep_it","wid","title","sentence"}                  the day-after "Keep it?" card
```

`startup` wishes fire when the first shell says `hello` after the engine starts.
Turning Wishes off (`consent` with `yes:false` after a yes) or `forget` tells the
service to forget her and deletes the token. `all_off` makes the engine send no
overlay and withdraws every trigger word.

**The compositor's half** is `src/aurwl/wishhook.{c,h}` (linked only when the
profile says `wishes="on"`): the shell calls `wishhook_set(words, apps)` with the
latest `triggers` line, and each frame drains `wishhook_take_word()` /
`wishhook_take_app()` into `typed` / `app` lines. The matcher sees only keys
delivered to a client window, keeps at most the 32 letters of the word being
typed, reports a registered word only when typed whole, and does nothing at all
while no word is registered. aurwl has no text-input-v3 yet, so it cannot tell
a password field: the shell must send `hold: password` for its own prompts, and
this is why Wishes ship off (D14).

**Off unless the machine says on (D14).** `aurwish` runs only when
`/etc/auros/features` says `wishes=on` (written by `build/forge` from the
profile) and `/etc/auros/policy.conf` does not say `wishes` is anything but
`on`. Otherwise it exits 0 at once; an image built without `wishes="on"` does
not contain it (`tools/wishesoff.sh`).

In a `shell` event the action is already resolved: `open_app` carries
`app` (a desktop id that exists), `open_website` carries `url` (from the
shipped site list, never from the model), `set_wallpaper` carries `color` or
`theme` (an installed theme id). The engine itself does `brightness`,
`volume` (through `src/aurshell/power.c`, the shell's own control path),
`play_sound`, `speak` and `speak_time` (`aurvoice say`, W2's).

## 4. What she sees and says (W2)

- A **Wish** button on every look's home and in Settings (the name and icon
  follow `docs/DESIGN-DIRECTION.md`): "What would you like your computer to
  do?" with a large text box and a large microphone button.
- Voice is transcribed **on the computer** (whisper.cpp class model; size and
  speed measured on a 2013 4 GB laptop; text box always works).
- Waiting: calm, honest ("Thinking about your wish…"), cancellable.
- Answer: the device's own sentence + **Yes, do that** / **No, thanks**; or
  the cloud's plain "I can't do that yet, but I can …"; or an answer to a
  question ("how do I print?") with an offer to do it.
- Spoken back aloud if she used her voice.

## 5. The cloud service (CL: `cloud/`) — v1, as built (follows §7)

One Cloudflare Worker and one Durable Object (`cloud/`, `docs/CLOUD.md`);
the same handler runs under Node for tests. It holds the Anthropic key; she
never has an account. **Only the engine (`aurwish`) talks to it** (the shell
never does). The engine treats every answer as hostile (§7.1): the checks
here save cost and keep answers useful; they are not the safety layer.
The wish schema both sides compile: `docs/wish-v1.schema.json`.

| Endpoint | Request (JSON body) | Response |
|---|---|---|
| `POST /v1/register` | `{install_id, version, consent_version, pow:{day, nonce}}` | `200 {token, expires_at}` |
| `POST /v1/wish` + Bearer | `{text, lang, schema:{v:1, triggers[], actions[]}, sensors:{compass, tilt, light}}` | `200 {kind:"wish", wish}` or `200 {kind:"cannot", missing, alt_wish?}` |
| `POST /v1/ask` + Bearer | `{question, lang, context:{look}}` | `200 {help_page_id, wish?}` (`help_page_id` is a file name in `/usr/share/auros/help/` without `.html`, or `null`: no page covers it) |
| `POST /v1/forget` + Bearer | `{}` | `204` (the token and its counters are gone) |
| `GET /v1/health` | – | `200 {ok:true}` |

Errors (JSON, plus a `Retry-After` header where there is a `retry_after`):
`400 {error:"request"|"too_long"}`; `400 {error:"pow", day, bits}`;
`401 {error:"token"}`; `429 {retry_after, text:"You've made lots of wishes today — more tomorrow"}`;
`503 {retry_after, text:"Wishes are resting for a little while"}`. The device
writes its own sentences (§7.3); `text` is only a fallback.

**Field rules.** `text`/`question`: 1–300 characters (code points). Body
≤ 8 KB. `lang`: a BCP 47 tag (`en`, `de`, `pt-BR`). `schema.triggers` /
`schema.actions`: the type names this engine supports (the model uses
nothing else; a wish with another type comes back as `cannot`). `sensors`:
which sensors exist (a sensor wish without one is `cannot`/`compass` etc.).
Unknown extra fields are ignored. `install_id`: 128 random bits made when she
agrees (§7.12), base64url (22 characters) or hex. `consent_version`: the
consent text she agreed to (`"1"`).

**`missing`** (why a wish can't be made; the device writes the sentence):
`unclear` (gibberish, say it another way) · `question` (a question, not a
wish: offer Ask AurOS) · `compass` / `tilt` / `light` (this computer has no
such sensor) · `install` · `files` · `messages` (e-mail, messages, calls) ·
`money` · `private` (passwords, personal details) · `security` (network,
firewall, updates, protections, accounts, remote access) · `other`.
`alt_wish`, when present, is the nearest wish it can do, schema-valid.

**Proof of work for `/register`.** Find a `nonce` (1–32 letters/digits) such
that `SHA-256("auros-register-v1:" + day + ":" + install_id + ":" + nonce)`
starts with `bits` zero bits (21 today: about 2 million hashes on average,
roughly 2 s in C on a 2013 laptop; it is luck, so one time in twenty it takes
three times longer). `day` is the UTC date `YYYY-MM-DD`; yesterday, today
and tomorrow are accepted. If her clock is wrong the 400 carries the
server's `day` and `bits`: compute again with those.

**Tokens and the device flow.** The token is opaque
(`[A-Za-z0-9_-]{22}.[A-Za-z0-9_-]{43}`); keep it with the `install_id` in a
0600 file in her home. It expires after 90 days (`expires_at`). On any 401:
register again silently (the same `install_id` gives the same token and keeps
her standing) and retry that request once. On 429/503: no automatic retry
(§7.9); show the device's sentence and allow a new try after `retry_after`
seconds. "Forget everything" / turning Wishes off: `POST /v1/forget`, then
delete the token and make a new `install_id` next time. Anthropic's copy of
past requests expires on Anthropic's schedule; the service cannot delete it.

**Limits** (one Durable Object holds them all). Per token and per day: 3
`/wish` and 3 `/ask` while the token is new; 20 and 20 once it is at least 7
days old and the service has returned it a wish (the service cannot see her
Yes; that is the nearest thing it can observe). A request Claude never
answered is not counted. `/register`: 3 per day per IPv4 /24 or IPv6 /64.
No other per-address limit. At most 40 Claude calls in flight; more get 503
at once. A daily budget (`DAILY_BUDGET_USD`) in fixed pools: 70 % established
tokens, 20 % new tokens, 10 % `/ask`; an empty pool answers 503 until UTC
midnight; the owner is told at 50 % (a log line, and a push to `ALERT_URL`
if set). A request whose estimated cost is over $0.01 is refused. Tokens on
the `BANNED` list get 401. No cache of answers.

**The model.** `claude-haiku-5-5`, thinking off, `max_tokens` 400 (`/wish`)
and 300 (`/ask`), a fixed system prompt (prompt-cached; the vocabulary, the
emoji allowlist and four example answers) and structured output constrained
to a small envelope `{kind, missing, wish_json}` (`{help_page_id, wish_json}`
for Ask). The wish is JSON text inside the envelope, because the API refuses a
grammar for the whole vocabulary (probed: it compiles about 20 alternatives,
the vocabulary has 26 shapes); the service parses it and holds it to
`docs/wish-v1.schema.json` plus the computer's lists, and answers `cannot` for
anything that does not pass. Her words go in the user message, escaped, as
data; everything else as quoted JSON. Anthropic 429/529 and timeouts: two
retries with backoff inside a 15 s deadline, then 503. Measured: $0.000089 a
wish, 1.2 s (docs/CLOUD.md §3a).

**Privacy.** Logs: one line per request with route, status, latency,
tokens, cost, `kind`/`missing`/`help_page_id` and a failure reason; never a
body, a header, a token, an id or an address (a CI test fails otherwise).
Stored: for each token, its first day and whether it is established (90
days); daily counters keyed by `HMAC(day key, token)` and `HMAC(day key,
/24)`, the day key deleted after 48 hours; daily spend. Nothing else.

**The address** comes from a signed package config (§7.11), not the image:
`docs/CLOUD.md` "How AurOS finds the service".

## 6. Order of work

1. W1 schema + validator + caps + tests (the safety core) — first.
2. CL service with a mocked Claude and the real schema; then real Claude
   behind the owner's key.
3. W2 panel, confirmation, My wishes; then voice.
4. End to end in a VM: say "potato" wish → Yes → type potato → potatoes.
5. Adversarial review of the whole chain (prompt injection, abuse, cost,

## 7. Contract v1 amendments (red team, 2026-10-23) — BINDING

A five-angle red team (injection, harm to her, privacy, abuse/cost,
product) attacked §1-§6. Everything below overrides the sections it names.
Lead's adjustments on top of the red team:

- **The owner's two examples are acceptance tests and must work**:
  "every time I type potato, fill my screen with potatoes" (typed_word
  `potato` → fill_screen 🥔; the emoji allowlist includes food, animals,
  hearts, flowers, stars, weather, celebrations) and "when my laptop points
  north, make the screen brighter" (sensor compass north → brightness
  set_percent 100; refused with `missing: compass` where there is none).
- **Quiet hours (21:00-08:00) apply to sound and speech, and to overlays from
  automatic triggers** (time, every, idle, sensor, startup, battery/charger,
  USB). An overlay from `typed_word` or `app_opened` is something she just did
  and is NOT held by quiet hours (still held during password entry, calls,
  screen sharing and fullscreen video per §3.5).
- Model choice is stream CL's, made with the `claude-api` skill and measured
  on the adversarial set; "Haiku-class" below is the default, not a rule.

### **1. §1.7 (new) — the cloud is untrusted.** Streams: W1, CL.
> "7. **The engine treats every cloud response as if an attacker wrote it.** A stolen key or a misbehaving model must not produce a harmful wish. Every rule in §2–§3 is enforced on the device, under a test named after the attack it stops (`test_scam_install`, `test_fake_support_text`, …). The service's own validation saves cost and does not count as a safety layer."

### **2. §2.2 — outward actions.** Merges inj1, inj2, inj12, her12, privacy2 and product13. Streams: W1 (rules), W2 (Yes screen), CL (prompt).
- Remove the `install_program` row. Add to §2: "Installing programs is not a wish in v1. The answer is `cannot` with `missing: install`."
- `open_website`: replace `url` with `site`, which must be one of her browser bookmarks or the shipped `sites.json`. Anything else is refused.
- New rule under the table: "`open_website` is allowed only with `when: now`. `open_app` is allowed only with `now` or `time`. A wish has at most one outward action, and it gets its own Yes screen that shows the destination in large text."

### **3. §2 and §2.2 — no model text reaches her unchecked.** Merges inj3, inj4, inj8, inj9, her7, her8, product8 and product12. Streams: W1 (filter), CL (response shape).
- Delete `title` and `summary` from the wish document. The device writes both from the trigger and actions, as §1.2 already does for the sentence.
- `/v1/wish` `cannot` becomes `{kind:"cannot", missing:<enum>, alt_wish?}`. `/v1/ask` returns `{help_page_id, wish?}`. The device writes every sentence and shows its own help page. The cloud counts `missing` values only.
- New §2.3 "Free text" (`fill_screen.text`, `show_message`, `remind`, `speak`):
> "NFC-normalise. Reject bidi and zero-width characters, any run of 5 or more digits, URLs and domain names, money amounts, and the words virus, infected, hacked, police, bank, Microsoft, Apple, AurOS, support, password. After normalising, every word must appear in her own wish text, apart from a shipped list of filler words. Lengths are counted in grapheme clusters, with a byte cap as well. Cards are labelled 'Your note:'. The confirmation shows the text word for word."
- `emoji` must come from a shipped allowlist of about 60 friendly emoji.
- §2.2 note: `speak` never claims to be the computer or a company.

### **4. §2.4 (new) — which triggers may use which actions.** Merges inj6, inj10, inj13, inj14, her4, her9, her10, her14 and product5. Stream: W1.
> "Recurring triggers (`every`, `idle`, `startup`, `sensor`, `typed_word`, `app_opened`, battery/charger/USB) may use only `fill_screen`, `play_sound`, `brightness`, `night_light` and `show_message`. On recurring triggers, `brightness` and `volume` accept `set_percent` only. `set_look`, `set_text_size`, `set_wallpaper` and `volume` are allowed only with `now`. `remind` is allowed only with `time`, at most 4 a day. `speak` is allowed only with `time` or `now`, at most 3 a day per wish. `every` is at least 30 minutes when the wish makes a sound. Triggers fire on the edge, when the condition starts, with hysteresis. Sensor and `idle` triggers wait at least 10 minutes before firing again, and any wish waits at least 60 s between overlays. No overlay flashes more than 3 times a second. Quiet hours run 21:00–08:00 for sound, speech and overlays; only a `time`+`remind` set for that time is exempt. A `typed_word` is at least 4 letters, not in the shipped stop-word list, and not in the shipped list of money, bank and login words."
- Floors for wishes: volume at least 20 %, brightness at least 30 %. Wallpaper must pass a contrast check against the theme.

### **5. §3.3 — limits.** Merges product4 and inj6. Stream: W1.
> "At most 6 actions an hour per wish and 20 overall. `time`+`remind` does not count toward the overall limit. Only the wish that broke a limit is paused. It resumes by itself after 1 hour, and she is told once."

### **6. §3.5 (new) "Never interrupt".** Merges her1, privacy3, privacy11 and her10. Stream: W1, with the compositor.
> "`typed_word` matching skips fields the compositor marks as sensitive (text-input-v3 `password` or `sensitive_data`). It keeps at most 32 characters in RAM, clears them when focus changes and never writes them anywhere. At most 10 trigger words. Visual and sound actions are held while the camera or microphone is on, during fullscreen video, while the screen is shared, on the lock or login screen, and while a password or permission dialog is open. Actions run after 3 s with no typing. The key or click that dismisses an overlay is used up and never reaches the app underneath. Cards never take focus, are never larger than half the screen, and there is at most one per wish; a new firing replaces the old card. A reminder can be set to 'show privately': the card says 'You have a reminder' until she presses it."

### **7. §3.6 (new) — Undo and Stop.** Merges inj10, her3, her13 and product11. Streams: W1, W2.
> "Before any change, the engine saves the previous value. For 10 minutes after a `now` wish, an **Undo my last wish** button sits next to Wish. My wishes has **Put everything back how it was**. After `set_look` or `set_text_size`, she is asked 'Keep this?', and it goes back after 15 s with no answer. Every overlay, card and wish-caused change shows 'Your wish "X" — [Stop this wish]' with a 44 px button that needs one click. The Help button lists today's wish activity ('What my wishes did today') and offers 'Stop all wishes'. `show_message` stays until she dismisses it."

### **8. §3.1 — the stored wish and missed reminders.** Merges product1, product2, product3, her2 and product15. Stream: W1.
- Each stored wish adds `id`, `v`, `status` (`on`, `off` or `paused:<enum>`), `created_at`, `created_by` (`text` or `voice`), `last_ran`, `notify` (`tell_me` for the first 3 runs, then `quiet`) and `if_missed` (`when_back` for `remind` with a 12-hour window, otherwise `skip`).
- Times are local wall-clock time and follow daylight saving. A missed reminder survives reboots and says "This was for 9:00". Reminder cards offer "Remind me in 10 minutes".
- The engine keeps every schema version it shipped and migrates on load. A wish it can't parse shows as "paused: needs a newer AurOS" and is never dropped.
- At login and after every update, the engine checks that each wish's app, theme and sensor still exist. If not, the wish is paused with a plain reason.
- The day after a recurring wish is created, a card asks "Keep it?". After 30 days, an unanswered card switches the wish off, except a `remind`.

### **9. §4 — confirmation and accessibility.** Merges her5, her6, her15, abuse9, abuse15 and product14. Stream: W2.
> "The confirmation shows 'You said: …' in large, editable text. The device's sentence always states when, what, how long and how to stop, with times, numbers and words in bold. She confirms by pressing the button; a spoken 'yes' does not count. Yes and No are the same size, neither has default focus, and there are 'Show me' and 'Read it to me' buttons. There are sentence templates for every shipped language; with no template, the sentence uses her setup language; with neither, the wish is refused. The microphone button is tap to start and tap to stop, stays open at most 30 s, and has no wake word. Audio stays in RAM and is dropped after transcription. If speech recognition is unsure, she is asked to repeat or type. One request at a time. The same text sent again within 30 s, or a text under 3 characters, is not sent. No automatic retries; `retry_after` is honoured, and Cancel stops the request upstream. Waiting gives up after 20 s. `speak` waits for the screen reader to finish. Overlays have an accessible name that includes the wish. Touch targets are at least 44 px, with a test at 1024×600. 'Stop', 'turn off wishes' and 'what can you do?' are handled on the device. On first open she sees 6 example wishes."
- §1.6: "Wishes she has already made run with no network at all." Ship a local gallery of about 20 templates whose blanks she fills by tapping. Making wishes from it survives outages and the spend cap.

### **10. §5 — cost and abuse.** Merges inj11, abuse1–13, product7 and privacy15. Stream: CL.
> "No secret in the image authenticates a client. A Bearer token is required on every endpoint except `/register`. `/register` is limited to 3 per IP per day (per /64 on IPv6) and needs a hashcash proof-of-work of about 2 s on a 2013 laptop. Daily quotas: 20 `/wish` and 20 `/ask` for a token at least 7 days old with one confirmed wish, 3 for a younger token. Input is at most 300 characters and the body at most 8 KB. The model is Haiku-class, with a prompt-cached system prompt and fixed `max_tokens` (400 for `/wish`, 300 for `/ask`). A request whose estimated cost is over $0.01 is refused. The budget has fixed pools: 70 % for established tokens, 20 % for new ones, 10 % for `/ask`, and no pool borrows from another. The owner is alerted at 50 %. Wishes has its own Anthropic workspace with a Console spend limit. A single Durable Object holds the counters and the limit on concurrent requests. Tokens expire after 90 days and re-register silently, and there is a ban list. Per-IP limits apply only to `/register`. A 429 says 'You've made lots of wishes today — more tomorrow'. A 503 says 'Wishes are resting for a little while'. The two are counted separately."
- The identical-request cache is deleted.
- The worked cost line in the contract: quota × cost per call × expected installs stays under the cap.

### **11. §5 — request shape.** Merges inj7, privacy4, privacy7, abuse14 and product2. Streams: CL, W1.
- New request: `{text, lang, schema:{v, triggers[], actions[]}, sensors:{compass, tilt, light}}`.
- Remove `apps[]`, `themes[]` and `existing`. The model returns `app_name` or `theme_name` as free text. The device matches it to what is installed, and no match means refused. Duplicates are found on the device.
- The cloud passes everything except her text to the model as quoted data.
- The cloud address moves to a signed package config.

### **12. §1.4 and §1.8 (new) — privacy.** Merges privacy1, 5, 8, 9, 10, 12, 13 and 14. Streams: CL, W2, W1.
- The consent text is written into the contract. It names the controller, a contact, the purpose, the processors (Cloudflare, Anthropic), the transfer to the US, retention (Anthropic deletes after 30 days, or keeps up to 2 years if its systems flag the request), her rights and a privacy-policy link.
- The owner signs Anthropic's data processing agreement and asks for zero data retention.
- Before sending, the device replaces digit runs of 5 or more and e-mail addresses with placeholders.
- `/v1/register` carries `consent_version`. A new version means she is asked again.
- `POST /v1/forget` deletes the token and its counters. Turning Wishes off, or pressing "Forget everything" (which also deletes `wishes.json`), calls it and makes a new `install_id`. The contract states plainly that Anthropic's copy expires on its own schedule and the service cannot delete it.
- `install_id` is a random 128-bit value made when she agrees.
- Counters are keyed by `HMAC(daily_key, token)` and `HMAC(daily_key, /24)`, and the daily key is deleted after 48 hours. A CI test fails if the service logs a request body or the Authorization header.
- Engine events go over a private socket that only `aurwish` can connect to. `aurwish` logs counts only. `wishes.json` is left out of any backup that leaves the machine.
- Wishes is off at build time in school-kiosk and in guest accounts, and there is a policy flag `wishes="off"` an administrator can enforce.
