# Wishes: AurOS's AI layer (contract v0)

> Owner, 2026-10-23: "there needs to be at least a bit of AI ... if I want an
> OS where every time I accidentally write the word potato it fills my screen
> with potatoes, or every time my gyro points north it makes the screen
> brighter, that needs AI ... some integration with Claude."

She says (or types) what she wants her computer to do. A few seconds later
AurOS tells her, in one plain sentence, what it will do, and she presses
**Yes**. From then on her computer does it. Every wish can be seen, switched
off and removed in one place. This file is the contract between the three
streams that build it: **W1** (the engine on the computer), **W2** (what she
sees and says), **CL** (the cloud service). Change it only by a commit that
all three read.

## 1. The safety model (non-negotiable)

1. **Claude never runs code on her computer.** The cloud turns her words into
   a *wish*: a small JSON document in the fixed vocabulary below. The engine
   on her computer validates it against its own copy of the schema and runs
   only what it knows. Unknown fields or types: the wish is refused.
2. **She confirms every wish** from its plain-words `summary`, generated by
   the cloud but re-rendered locally from the validated fields (the device
   writes its own sentence; it never shows unvalidated model text as the
   description of what will happen).
3. **Nothing a wish does can hurt her**: no files deleted or moved, no
   messages or e-mails sent, no purchases, no passwords, no network or
   security settings, no turning off updates/firewall/scam guards, no
   keystrokes leaving the computer. Hard caps in the engine (§3.3) bound
   every action. Any overlay vanishes at the first key or click.
4. **Privacy**: the only thing sent is the text of her wish (or question),
   her language, and a capability list (which sensors and looks exist, which
   programs are installed). Never keystrokes, file names, contacts, location.
   First use shows one plain consent screen; "No" leaves Wishes off.
5. **Typed-word triggers stay local**: the compositor matches what she types
   against the few registered trigger words and emits only "word X typed".
   Nothing she types is stored or sent.
6. **Offline / service off**: Wishes says so in one line and the rest of the
   computer is unaffected.

## 2. The wish document (v1)

```json
{
  "v": 1,
  "title": "Potatoes!",
  "summary": "Every time you type the word potato, your screen fills with potatoes for 3 seconds.",
  "when": { "type": "typed_word", "word": "potato" },
  "do": [ { "type": "fill_screen", "emoji": "🥔", "seconds": 3 } ],
  "enabled": true
}
```

`title` ≤ 40 chars, `summary` ≤ 160 chars, `do` 1–4 actions.

### 2.1 `when` (exactly one)

| type | fields | notes |
|---|---|---|
| `now` | – | a one-off change (e.g. "make the text bigger") |
| `typed_word` | `word` (2–32 letters) | local match, case-insensitive, whole word |
| `time` | `at` "HH:MM", `days` ["mon",...] or omitted = every day | |
| `every` | `minutes` 5–1440 | |
| `startup` | – | after she logs in |
| `app_opened` | `app` (desktop id from caps) | |
| `battery_below` | `percent` 5–50 | |
| `plugged_in` / `unplugged` | – | charger |
| `usb_inserted` | – | |
| `idle` | `minutes` 1–240 | no input for that long |
| `sensor` | `sensor` ∈ `compass`,`tilt`,`light`; `compass`: `heading` ∈ north/east/south/west, `tolerance_deg` 5–45; `tilt`: `orientation` ∈ normal/left/right/upside_down; `light`: `below_lux` / `above_lux` | only offered when caps list the sensor |

### 2.2 `do` (1–4, run in order)

| type | fields | engine caps (§3.3) |
|---|---|---|
| `fill_screen` | `emoji` (one emoji) or `text` (≤ 24 chars), `seconds` 1–10 | ≤ 10 s, ≤ 12/hour, dismiss on any input |
| `show_message` | `text` ≤ 140, `seconds` 3–60 | calm card, dismiss on input |
| `remind` | `text` ≤ 140 | a reminder card that stays until she presses OK |
| `speak` | `text` ≤ 200 | on-device voice |
| `play_sound` | `sound` ∈ chime, bell, birds, applause, gentle | volume ≤ her current level |
| `brightness` | `set_percent` 10–100 or `change_percent` −50..+50 | never below 10 % |
| `volume` | `set_percent` 0–80 or `change_percent` −50..+50 | never above 80 % from a wish |
| `open_app` | `app` (desktop id from caps) | |
| `open_website` | `url` https only, no IP literals, no credentials in URL | shown in the confirmation; S2's scam guard applies |
| `install_program` | `flathub_id` | always asks her again in the store; S2's remote-access warning applies |
| `set_look` | `look` ∈ taskbar, dock, rail, tiles | |
| `set_text_size` | `size` ∈ normal, bigger, biggest | |
| `set_wallpaper` | `color` (#RRGGBB) or `theme` (installed theme name) | |
| `night_light` | `on` bool | |

## 3. The engine on her computer (W1: `src/aurwish/`)

1. `aurwish` runs as her user (never root), reads/writes
   `~/.local/share/auros/wishes.json` (0600), validates every wish with the
   v1 schema compiled in (no network schema fetch), and runs triggers/actions.
2. Event sources: compositor events (typed words, app opened, idle), upower
   (battery, AC), udev (USB), iio-sensor-proxy (compass, tilt, light),
   timers. Actions via the shell's existing control paths (brightness,
   volume, look, text size, theme) and an overlay surface drawn by the shell.
3. **Caps** (in code, tested): the table limits above; a global limit of
   60 actions/hour across all wishes; a wish that hits a cap is paused and
   she is told once, plainly; a crash or bad file never blocks login
   (wishes are skipped, the shell starts).
4. "My wishes" (Settings): each wish's sentence, an on/off switch, Remove;
   "Turn off all wishes". Removing the last wish leaves nothing running.

## 4. What she sees and says (W2)

- A **Wish** button on every look's home and in Settings (the name and icon
  follow `docs/DESIGN-DIRECTION.md`): "What would you like your computer to
  do?" with a large text box and a large microphone button.
- Voice is transcribed **on the computer** (whisper.cpp class model; size and
  speed measured on a 2013 4 GB laptop; text box always works).
- Waiting: calm, honest ("Thinking about your wish…"), cancellable.
- Answer: the device's own sentence + **Yes, do that** / **No, thanks**; or
  the cloud's plain "I can't do that yet, but I can …"; or an answer to a
  question ("how do I print?") with an offer to do it.
- Spoken back aloud if she used her voice.

## 5. The cloud service (CL: `cloud/`)

Portable fetch-handler service (runs on Cloudflare Workers; also Deno/Node
for tests). Holds the Anthropic key; she never needs an account.

| Endpoint | Request | Response |
|---|---|---|
| `POST /v1/register` | `{install_id, version}` | `{token}` (opaque, per install) |
| `POST /v1/wish` | `{text, lang, caps:{sensors[], apps[], looks[], themes[]}, existing:[titles]}` + `Authorization: Bearer` | `{kind:"wish", wish}` · `{kind:"answer", text, wish?}` · `{kind:"cannot", text}` |
| `POST /v1/ask` | `{question, lang, context:{look}}` | `{kind:"answer", text, wish?}` (help grounded in AurOS's help pages) |
| errors | | `429 {retry_after, text}` (her limit), `503 {text}` (busy/budget), `400` |

- Claude produces the wish through **structured output** constrained to the
  v1 schema; the service validates again before answering.
- Limits: per token per day, per IP per day, global daily spend cap (a
  plain "Wishes are resting until tomorrow" when hit), identical-request
  cache.
- Logs: counts, latency, cost. Never the text of a wish.
- Deploy: `.github/workflows/cloud.yml` with the owner's secrets
  (`docs/OWNER-SETUP.md`); never a key in the repository or the image.
- The address AurOS uses is baked at build time (like the repository
  address) so a move is one variable.

## 6. Order of work

1. W1 schema + validator + caps + tests (the safety core) — first.
2. CL service with a mocked Claude and the real schema; then real Claude
   behind the owner's key.
3. W2 panel, confirmation, My wishes; then voice.
4. End to end in a VM: say "potato" wish → Yes → type potato → potatoes.
5. Adversarial review of the whole chain (prompt injection, abuse, cost,
   privacy, overlay that traps her) before it ships switched on.
