# Stream S4 — theft protection (encrypted disk + PIN, owner decision D9)

For a zero-context engineer. Read this, then `docs/security/THEFT.md` (the
design, with what building it measured), `docs/security/THEFT-UX.md` (the
one page for the owner: what she sees), `docs/handoff/FIELD-MANUAL.md`
(environment, homebase rules, disk budget).

## Goal

AurOS's root partition is LUKS2, opened by a 4-6 number PIN on a
full-screen AurOS page at start (TPM 2.0 + PIN; an honest no-TPM
fallback), a 24-number rescue code she keeps on paper, Adiantum without
AES-NI, a re-seal path when the TPM's view of the computer changes.

## SWITCHED OFF. Hard rule for session B

Nothing here runs in the default install. The image only carries inert
files under `/usr/lib/auros/lock/` (no unit enabled, no initramfs hook
linked, no menu change) until `lockctl prepare` is run, and nothing runs
it. Switching it on needs the lead's yes (the VM proof below is green).

## Traps (each cost time)

- NEVER stop or SIGKILL a running `theftunit` / `cryptsetup reencrypt` on a
  shared host: torn down mid-hot-zone it leaves `<name>-hotzone-backward`
  and `-overlay` dm devices SUSPENDED and every `sync` on the host hangs.
  Recover: `dmsetup resume <name>-hotzone-backward`, then `-overlay`
  (an ubuntu container + `apt-get install dmsetup`), then `cryptsetup close
  <name>` and `losetup -d`. Power cuts belong in the VM.
- homebase has a real vTPM and privileged containers see it: the tests
  delete `/dev/tpm*` in the container and point every call at swtpm.
- homebase's disk: stay under the FIELD-MANUAL budget. The VM test's
  working disk is a tmpfs (`--tmpfs /t:size=9g -e TMPDIR=/t`, `hb run 14 1.5`);
  the unit suite needs real storage (loop + dm-crypt do not work on a
  tmpfs-backed loop) and ~4 GB: check `df` first.
- `hb run` de-duplicates identical submissions for 5 minutes (use `--name`);
  `hb cancel` asks for confirmation (`YES=1`).
- The initramfs: update-initramfs copies `scripts/` as it finds them (install
  copies, not links); stderr there goes nowhere (log to `/run/auros-lock.log`
  and `/dev/console`); no head/tail/tr/cut (theftunit runs encrypt-init with
  only the tools an initramfs has); cryptsetup needs `/run/cryptsetup`,
  `DM_DISABLE_UDEV=1` (cryptsetup 2.7.0 has NO `--disable-udev`), and
  `af_alg`+`algif_skcipher` for Adiantum.
- systemd 255's TPM token answers -131 to a wrong PIN, a lockout and a
  different chip alike; the page reads the chip's own lockout counter.
- LUKS2 refuses keyslot changes during the online pass: PIN only after it.
- Without a TPM the firmware does not reset on the first start (the VM's
  prime boot is then already the plain boot).
- Do not install `cryptsetup-initramfs` (its console prompt would replace
  the page). grub cannot read the LUKS2 root: the boot set lives on
  AUROS-BOOT under `/auros/`.
