For an engineer with zero context. Brief: `docs/handoff/STREAMS.md`, row S3;
environment: `docs/handoff/FIELD-MANUAL.md`. Branch `main` only.
Last updated: see `git log -1 -- docs/handoff/streams/S3.md`.

## Goal

Fuzz every parser of untrusted input we wrote, under ASan+UBSan, fix every
crash with a regression test, then add hardening compiler flags to every C
build and prove them with a checksec-style test.

## Hardening (done, `f256364`)

- `build/cflags`: `HARDEN_CFLAGS` (forge), `HARDEN_STATIC` (`-static-pie`:
  staging init + aurscreen), `HARDEN_PE` (aurbridge .exe). Ferry's helpers
  carry the same line in `src/ferry/install.sh`.
- `tools/checksec.sh FILE...` is a gate in build/forge (8 binaries),
  build/staging (2) and build/aurbridge (2). `--selftest` proves every
  check fails on a binary built without its flag (ELF 7/7, static 5/5,
  PE 1/1). ssp/fortify cannot be read from a static binary (libc's copies
  are always there); stack-clash leaves no mark: both are said, not hidden.
- `.github/workflows/fuzz.yml`: regress.sh + checksec selftest on every
  push touching what they check (green on `f256364`).

## Traps

- gcc's UBSan does not report the misaligned load clang's does: regress.sh
  uses clang when present.
- A regress file must fail the OLD code under the CURRENT harness: when a
  harness changes, re-derive its reproducers (finding 4's first reproducer
  was a harness artefact and was replaced).
- libwayland numbers globals in creation order; fuzz_aurwl assumes wl_shm
  is created just before wl_compositor (wl_display_init_shm first).
- Ubuntu's gcc already defaults to FORTIFY/SSP/PIE/CET; only `-z now` and
  `-static-pie` change anything there. The selftest builds the weak
  program with every flag explicitly turned off.
- `file` says "static-pie linked", not "statically linked": build/staging's
  check accepts both.
