# Stream A2 — the install engine's Windows-side fast path

Written by the fast-path agent of 2026-10-23 for an engineer with zero
context. Kept current after every push. Read this, then
`docs/AURBRIDGE.md` ("Fast path: status") and decisions D1, D2, D10, D11
in `docs/handoff/SESSION-2026-10-23.md`.

## Goal

AurOS installs beside Windows in ~10 minutes and BitLocker PCs never
need decrypting. Today (the shipped, legacy path) the wizard downloads
the image to `C:\AurOS\`, arms BootNext, and after the restart the
staging initramfs (`src/aurstage/`) shrinks NTFS offline (ntfsresize),
copies the image, commits the GPT. BitLocker PCs must fully decrypt
first (hours). The fast path moves the shrink (Windows' own online
shrink, `Resize-Partition`) and the image write (raw, into the
unallocated gap only, fenced) into Windows during the download, so
staging only verifies and commits (~1 minute) and never touches NTFS.

Owner-approved, user-visible behaviours D10 (Wi-Fi across), D11
(BitLocker paused for one restart) and a "Put Windows back" startup task
are in the session log; see "BLOCKED" below for their status here.

**Rule: the wizard selects the fast path only once every step below is
proven green. The legacy path must keep working and its tests stay
green.**

## Traps hit

- `git fetch origin main` in a worktree of the lead's checkout updates only
  FETCH_HEAD (the remote's fetch refspec is the old branch): use
  `git fetch origin +main:refs/remotes/origin/main` before rebasing.
- Never `git checkout <path>` on a dirty tree to undo a test mutation: it
  reverted real edits once (001014f shipped half a change).
- GitHub keeps ONE pending run per concurrency group: dispatching several
  runs in a row cancels all but the last. Dispatch the next only after the
  previous started (scratchpad `mutants.sh` does this).
- pwsh steps exit with the last native command's exit code: end a step
  whose last command is an expected failure with `exit 0`.

- PowerShell output parsing: never "last number in the output"; print
  `KEY=value` markers.
- Disk space in the container is ~5-12 GB: give the worktree its own
  `work/` with only `work/forge/desktop/rootfs` symlinked from the main
  checkout, never write into the main checkout's `work/`.
